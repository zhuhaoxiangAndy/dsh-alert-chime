# tools — 用音符/音调描述生成音频

不依赖插件系统、不依赖 profile、不依赖任何第三方包。**这是有意的**：提示音要"在某个时刻播放"这件事，反复被 DSH 升级和 profile 隔离打断；而"把一段描述合成为音频"是纯计算，谁也拿不走。

## 快速开始

```powershell
# 描述 -> WAV
node tools/synth.mjs "C5:q E5:q G5:h" --out chime.wav

# 校验生成的 WAV（解析回容器与采样，不是只看文件存在）
node tools/verify-wav.mjs chime.wav

# 生成全部示例并逐个校验（可复现的全部测试）
node tools/smoke.mjs
```

## 描述语法

写法尽量贴近"哼出来"的样子：

| 写法 | 含义 |
| --- | --- |
| `C5:q` | C5 音，四分音符 |
| `A4:h` | A4（440 Hz），二分音符 |
| `880Hz:0.3s` | 直接给频率与绝对时长 |
| `-:q` | 休止 |
| `[C4+E4+G4]:h` | 和弦（同时起音） |
| `C5:q.` | 附点四分音符 |
| `C5:200ms` | 绝对时长 200 毫秒 |

音名用科学音高记号（A4 = 440 Hz、C4 = 中央 C），变化音写 `#` 或 `b`（`C#5` / `Db5`，也接受 `Cs5`）。

时值字母：`w` 全音符、`h` 二分、`q` 四分、`e` 八分、`s` 十六分、`t` 三十二分；尾部 `.' 每个附点加一半；裸数字按拍计；`NNNms` 与 `N.Ns` 为绝对时长。拍速由 `--tempo`（默认 120）决定。

## 参数

```
--out <path>       输出 WAV（必填）
--wave <name>      sine | square | saw | triangle   （默认 sine）
--rate <hz>        采样率                            （默认 44100）
--tempo <bpm>      拍速                              （默认 120）
--gain <0..1>      增益                              （默认 0.8）
--attack <ms>      起音斜坡                          （默认 8）
--release <ms>     释音斜坡                          （默认 60）
--tail <ms>        末尾静音                          （默认 120）
--normalize        归一化到 -0.2 dBFS 而不是 0 dBFS
--spec-file <path> 从文件读描述
--dry-run          只打印解析出的音符与预估长度
--help             帮助
```

## 几个实现上的取舍

- **限带加法合成**：方波/锯齿/三角不是用波形表硬切，而是叠加谐波并把 Nyquist 以上的谐波全部丢掉，所以不会产生混叠噪声。谐波数上限 64，够用且不浪费。
- **归一化留余量**：目标峰值 0.98 而不是 1.0。满刻度量化后正好是 int16 的 32767，与"削波样本"无法区分，下游任何增益都会立刻削波 —— 第一版就是这样被 `smoke.mjs` 抓出来的。
- **每个音符都有起音/释音斜坡**：硬起硬停是能听见的爆音（click）。
- **WAV 按 chunk 遍历解析**：`verify-wav.mjs` 不假设固定的 44 字节头，遇到额外 chunk 也能读对；同时校验 RIFF 长度、byte rate、block align 三者自洽。

## 已验证

`node tools/smoke.mjs` 会生成 `audio/` 下四个示例并对每个断言：容器可解析、时长与描述一致、峰值有效且无削波；另外四个负向检查（无法识别的音名、无法识别的时值、空描述、非 WAV 输入）必须抛错。全部通过才算 PASS。

## 不依赖插件：监听会话日志触发（`watch.mjs`）

插件那条路在 0.2.1-rc.5 里已经断了（动态插件工具不存在，desktop profile 又只能从界面装插件）。但**会话日志是磁盘上已经存在的稳定事实**，所以可以直接跟着它。

```powershell
# 跟着最新的会话日志，有事就响（保持这个窗口开着）
node tools/watch.mjs

# 只看它「本来会对哪些事件触发」，不播放声音
node tools/watch.mjs --self-test

# 固定某一个日志、指定声音、指定轮询间隔
node tools/watch.mjs --session-log "<...>\session.v4.jsonl.zstd" --wav audio/idle.wav --interval 700
```

会触发的事件：

| 事件 | 含义 | 声音 |
| --- | --- | --- |
| `approval/asked` | 有审批在等你点 | `--wav` |
| `turn/end` | 一轮跑完 | `--wav` |
| `tool/call` 且 `data.name === 'ask_user_question'` | 向你提问 | `--wav` |

### 这个方案依赖的几个实测事实

1. 日志路径：`$DSH_HOME/sessions/<工作区slug>/<session-id>/session.v4.jsonl.zstd`。
2. **日志是逐帧追加的 zstd**：一次性 `zstdDecompressSync` 或流式 `createZstdDecompress` **都只得到第一帧**（实测 1.3 MB 只解出 233 字符的会话头）。必须按帧魔数 `28 B5 2F FD` 切分后逐帧解压 —— 实测 **140/140 帧全部解压成功**，恢复 1089 个事件。
3. 事件词表里有 `approval/asked`、`turn/end`、`tool/call`；工具名在 `event.data.name`。
4. 只解**新增帧**（按字节偏移追踪），稳态下每次只读末尾几个字节；首次启动**跳过历史**，避免把一场会话里的旧告警全部补响一遍。
5. 正在写的最后一帧会解压失败，视为"未完成"，下一轮重试。

### 已知局限（诚实说明）

- **强耦合于日志格式**：`session.v4` 里字段变了就要跟着改。这是它相对插件的代价，好处是升级不会"卸载"它。
- **默认跟"全局最新"的那个日志**：多会话同时干活时可能跟错会话，用 `--session-log` 固定。
- 靠轮询（默认 700 ms），有不到一秒的延迟。
- 只在**你手动保持它运行**时有效；要开机自启需要自己加计划任务。

## 和系统提示音的关系

生成出来的 WAV 也可以直接当系统提示音：Windows 设置 → 个性化 → 主题 → 声音，把某事件的声音指到你的 WAV 上。这条路零脚本、零进程，只是触发时机由 Windows 决定，不由 DSH 决定。
